## New findings from this run

1. In headless roles, `--allowedTools` blocks `; echo "exit=$?"` and some `$(...)` gate
   commands, which need an approval prompt that `claude -p` cannot answer. Roles cannot always
   print an exit status. The `fmt` gate ran for some roles and not for others.
2. The `--allowedTools` example names `make` and `gofmt` from the `config.md` example. It should
   say to derive the list from this project's `gates.*`.
3. "Take it out of draft first" assumes item PRs are opened as drafts, but no step says to open
   them that way.
4. No rule says whether an item counts as done when its instructions require an out-of-region
   write that the role had to revert.
5. The role reverted the generator's `mobile/` write before running `--check`, so no failing
   output was recorded. The skill should say to run `--check` first, then revert.
6. Handover updates are only pushed with the next orchestrator commit, which in this sprint was at
   the end.
7. The closing documents are committed before the integration PR exists, so the summary cannot
   cite its number or CI run.
8. The MR template fits items, not the integration PR.
9. Headless roles load the operator's own `CLAUDE.md`, which here prescribed a different dispatch
   command; every role reported the conflict.
