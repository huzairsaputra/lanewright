## 3. Desain

- **Tugas:** repo Go baru (`example.com/hardtrial`), satu sprint 4 item (BE-1 sampai BE-4) dengan satu aturan otorisasi tersirat (BE-3 dan BE-4, berbasis `X-User-ID`), jebakan wilayah pada generator (BE-2) dan ketergantungan antarmodul. Teks tiket dibuat sama kata demi kata dalam dua bentuk (Lanewright dan scrum-kit). Uji penerimaan tersembunyi (per item, termasuk aturan tersirat) tidak pernah terlihat oleh agen.
- **Fase inti (tahap 1):** 7 sel model × 2 arm × 2 ulangan = 28 run. Arm A: tanpa pack. Arm C: Lanewright mode portabel (satu sesi memerankan tiap peran). Pasangan menurut harga daftar: Haiku 5.5 dengan `gpt-6-luna`; Sonnet 5.5 dengan `gpt-6.1-sol`; Opus 5.5 dengan `gpt-5.6-sol`; ditambah `gpt-6-astra` dengan skema yang sama seperti sel Opus.
- **Tahap 2 (aturan tetap):** sebuah model dianggap **tidak konsisten** bila, pada salah satu armnya, kedua ulangan berbeda pada (a) jumlah butir DoD terpenuhi (selisih ≥ 1), atau (b) jumlah item lulus uji tersembunyi (selisih ≥ 1), atau (c) biaya notional atau waktu dinding (selisih > 30% dari rata-rata kedua run). Untuk model itu, **kedua arm** mendapat ulangan ketiga (maksimal +14 run). Tidak ada ulangan tambahan karena alasan lain.
- **Fase tambahan:** setelan S2 (Sonnet/Sonnet), S3 (Opus/Opus), S4 (Sonnet orkestrator, Opus peran), S5 (Haiku orkestrator, Sonnet peran) × 2 pack (Lanewright mode Claude Code, scrum-kit 1.5.0) × 2 ulangan = 16 run, hanya Claude. scrum-kit memakai salinan plugin yang hanya berbeda pada baris `model:` (dicatat sebagai modifikasi). S1 (semua Haiku) dibuang.
- **Pengendalian:** tingkat nalar dikunci `medium` (`CLAUDE_CODE_EFFORT_LEVEL=medium` dan `--effort medium` untuk Claude; `model_reasoning_effort="medium"` untuk Codex); isolasi `CLAUDE.md` pengguna, plugin kerja, dan MCP; `CODEX_HOME` kosong per run (hanya autentikasi); tanpa kunci API (`apiKeySource` harus `none`, bila tidak run dibatalkan); satu repo privat per run dengan CI yang sama; prompt DoD yang sama untuk semua arm ditambah satu baris per arm; keputusan PO yang sama di semua arm; run serial, urutan selang-seling dan diacak dengan benih tercatat (`plan_order.py`); batas waktu dinding 90 menit per run.
- **Batas langganan:** gerbang sebelum run (`5 jam + estimasi ≤ 90%` dan `7 hari + estimasi ≤ 95%`) dan pemutus pada 95% jendela mana pun (`limits.json`). Run yang terputus batas **dilanjutkan dan ditandai**, tidak dibuang.
- **Jendela segar (baru di v2):** sebuah run yang estimasinya sendiri melebihi batas gerbang (tidak muat satu jendela) hanya boleh dimulai bila jendela itu segar (terpakai ≤ 10%), selain itu menunggu reset. Sebelum pelindung ini ada pun, run yang terputus batas dilanjutkan dengan `--resume` dan ditandai.
- **Gangguan platform (baru di v2):** run mulai hanya bila status GitHub Actions operasional (`harness/ci_health.py`); run yang CI-nya gagal tanpa job ditandai `invalid` dengan alasan `ci-platform-failure`, tetap dilaporkan dan tidak dibuang.
